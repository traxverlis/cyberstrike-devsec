## Responsible Use Guidelines

### What Is Permitted
- Scanning your own systems and infrastructure
- Scanning systems for which you have a signed authorization document
- Testing in dedicated lab environments isolated from production
- Educational use in controlled, sandboxed environments
- Bug bounty programs where scanning is explicitly permitted in scope

### What Is Not Permitted
- Scanning systems without written authorization
- Using Level 2/Level 3 capabilities against production systems without proper consent
- Bypassing or spoofing the consent token system
- Automating attacks against third-party systems
- Distributing scan results that expose third-party vulnerabilities without responsible disclosure

## Reporting a Vulnerability in This Tool

If you discover a security vulnerability **in CyberStrikeAI DevSec itself** (not in a system you are scanning), please follow responsible disclosure:

### 1. Do NOT open a public GitHub issue

Public disclosure of unpatched vulnerabilities puts users at risk. We ask that you give us time to remediate before any public disclosure.

### 2. Email the security team

**Contact:** `security@cyberstrike.ai`

**PGP Key:** Available at `https://cyberstrike.ai/.well-known/security.txt`

**Include in your report:**
- Type of vulnerability (e.g., RCE, injection, path traversal, authentication bypass)
- File(s) affected with line numbers if applicable
- Step-by-step reproduction instructions
- Proof of concept (screenshots, logs, or code)
- Potential impact assessment
- Your name/handle for credit (optional)

### 3. Expected Timeline

| Milestone | Target |
|-----------|--------|
| Acknowledgement | Within 48 hours |
| Initial assessment | Within 5 business days |
| Status update | Every 7 days |
| Patch release | Within 30 days (critical), 90 days (high/medium) |
| Public disclosure | After patch is released and users have had time to update |

## Responsible Disclosure Policy

We follow the principle of **coordinated vulnerability disclosure**:

1. **Reporter** notifies us privately with full details
2. **CyberStrikeAI security team** acknowledges within 48 hours
3. **We investigate** and develop a fix
4. **We release** a patched version
5. **Joint disclosure** — we publish a security advisory and credit the reporter
6. **Embargo period** — we request a minimum 30-day embargo from the time of our acknowledgement

We will not pursue legal action against security researchers who:
- Act in good faith
- Do not access or exfiltrate user data
- Do not disrupt services
- Follow this disclosure policy

## Security Best Practices for Deployers

If you deploy CyberStrikeAI DevSec in your organization:

### Protect the Consent System
```bash
# consent-token.json must never be committed
echo "consent-token.json" >> .gitignore
echo "consent/*.json" >> .gitignore

# Restrict file permissions
chmod 600 consent/consent-token.json
```

### Protect API Keys
```bash
# Never hardcode API keys — use environment variables
export NVD_API_KEY="your-key-here"
export SEMGREP_APP_TOKEN="your-token-here"

# Or use a secrets manager
# AWS Secrets Manager / HashiCorp Vault / GitHub Secrets
```

### Audit Logs
- Audit logs generated by `scripts/audit-trail.py` contain sensitive pentest data
- Store audit logs with appropriate access controls (read-only, role-based)
- Comply with your organization's data retention policy
- Encrypt audit logs at rest if they contain vulnerability details

### Network Isolation
- Level 2/Level 3 scans MUST run from isolated network segments
- Never run active scans from production environments
- Use dedicated jump hosts or CI/CD runners with egress filtering

## Compliance Notes

### GDPR / Data Protection
- Scan results may contain personal data (usernames, emails found in secrets, etc.)
- Treat scan reports as sensitive data subject to GDPR Article 32 (security of processing)
- Do not store scan reports longer than necessary
- The `.gitignore` excludes `*.pdf` and `reports/output/` by default — do not override this

### PCI-DSS
- If scanning cardholder data environments, ensure your Rules of Engagement explicitly cover CDE scope
- Level 3 pentest reports may be required for PCI-DSS Requirement 11.3 compliance
- Retain reports per PCI-DSS retention requirements (minimum 12 months)

### ISO 27001
- Use `roles/devsec-audit.yaml` for ISO 27001-aligned security assessments
- Map findings to ISO 27001 Annex A controls using the built-in mapping in `devsec-full-report.md`
